## Build any real-world application using Kiro.

The theme is open. Create something that solves a genuine problem and can be run by the judges.

Web AppCLI ToolProgramming LanguageAI AgentAPIAutomation ToolDesktop ToolMobile ApplicationGame

ThemeSpec to Ship: Build, Test, and Launch with an Agent.

ToolingProjects must be built using Kiro and clearly demonstrate meaningful Kiro use in the README and demo video.

Quality barSubmissions must install or run consistently, match the demo and README, and avoid simulated or hard-coded features presented as working functionality.

ValueProjects should demonstrate real-world value and solve a genuine problem.

OriginalityWork must be original and created during the competition period, with meaningful human direction and responsibility.

SetupJudges must be able to run the project from a complete public repository with clear setup and testing instructions.

Rules and Eligibility

## Short rules summary

This is a summary only. Read the [full hackathon rules](https://codingagents.fyi/hackathon/kiro/rules/) before submitting your entry.

SubmissionsSubmit during the Competition Period, from August 8, 2026 at 00:00 UTC through August 23, 2026 at 23:59 UTC. Each submission needs a public repository, the project's `.kiro` directory, complete README, working demo or test build, demo video, testing instructions, and any required test credentials.

Kiro useEvery project must be built using Kiro. The README and demo video must show meaningful Kiro usage.

JudgingSubmissions go through a pass-or-fail eligibility and viability screen, then qualifying projects are scored using the 100-point rubric.

Evaluation criteria

- Application Quality: 40 pts
- Kiro Usage: 20 pts
- Documentation: 20 pts
- Innovation and Potential: 15 pts
- Presentation: 5 pts

EligibilityEntrants must meet the age of majority where they live. Individual participants and teams of two or three are allowed, except where prohibited by law or conflict rules.

Original workProjects must be original work created during the Competition Period. Open-source libraries, frameworks, development tools, and generic starter templates are allowed.

SupportPrior financial or preferential support from the Host, Sponsor, or their affiliates must not create an actual or apparent conflict of interest.

AccessJudges must be able to access the repository, demo video, working application or test build, and setup instructions without making a payment.
